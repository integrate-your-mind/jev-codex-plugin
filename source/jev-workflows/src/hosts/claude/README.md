# Offline Claude routing bridge

This adapter keeps the first request unchanged. A trusted ordinary `PostToolBatch` command consults the existing decision service and publishes one immutable record plus model-visible advice. The native module only consumes a matching record. It never imports Node, reads a credential, calls MCP, executes an alternative tool, or changes a permission decision.

`UserPromptSubmit` records bounded, redacted objective facts through the existing private task-context writer. It does not consult the provider. The native prompt event invalidates prior batches immediately, including queued prompts. Scope includes workspace, session and agent. Semantic identity includes objective, evidence, policy, configured catalog, provider and credential epoch. Delivery tool IDs are separate from semantic identity.

The native consumer joins streamed tool IDs, ordinary completed tool calls and the final response's tool count to the immediately preceding inference's turn and index. Missing, partial, duplicate, stale, out-of-scope or ambiguous joins preserve the incoming pair. A changed incoming model or effort also preserves it, protecting concurrent human changes. Readable private records are insufficient without that in-memory join, so reloads preserve the incoming pair.

Profiles must be explicitly verified for the configured host/provider and must have a supported named effort. A configured transition map authorizes upshift or lateral changes. Numeric effort selections remain unsupported. Downshift remains unsupported because the ordinary payload cannot prove semantic subtask completion or absence of background work. A resolved synchronous batch is not that proof.

Records live under the existing private state root at `routing-v1/claude/<session>/<agent>/<batch-key>.json`, are published with an exclusive hard-link operation and expire for application no later than the absolute producer deadline. On producer writes, an ownership-safe lock serializes short claim/pruning operations. Owned metadata older than ninety days is pruned. Pinned records, `.pinned` proof markers, unknown files, symlinks and recently restored files remain preserved. Claims suppress duplicate batch delivery. Shared semantic claims and provider-specific outage state suppress unchanged consultations. There is one global five-second producer wait budget. A late service result or delayed final publication cannot leave an applicable selection. No raw transcript or raw tool arguments/results enter the provider packet; local digests identify those observations. Bounded redacted objective and explicit evidence references remain useful decision context.

The classic package remains the default. `--native-routing-config /absolute/path` opts into the native edition and requires the same explicit state root supplied to `--state-directory`. Marked packages are staged and atomically replaced; failed replacement retains the previous package. Configuration accepts public routing metadata only. Existing credential paths are propagated without reading their values during packaging. No installation, migration, new authentication mechanism or live inference is performed by this work.

## Feature map and checks

| Journey | Code | Verification |
| --- | --- | --- |
| Preserve or apply the next request | `bridge.ts`, `mod.ts` | `tests/claude-bridge.test.ts` |
| Produce advice once within the deadline | `producer.ts`, `src/claude-hook.ts` | Producer concurrency, timeout and publication tests |
| Keep old package behavior and opt in explicitly | `scripts/package-claude.mjs`, `templates/claude/hooks/` | `tests/claude-package.test.ts` |
| Match the public host interface | Actual `Register` import from `claude-code` | `npm run typecheck`, pinned public declarations fixture |

Run `node scripts/prepare-claude-types.mjs`, then `node --import tsx --test tests/claude-bridge.test.ts tests/claude-hook.test.ts tests/claude-package.test.ts tests/claude-retention.test.ts` and `npm run typecheck` from the source package. Both `npm test` and `npm run typecheck` perform the preparation automatically. Package tests bundle the actual native source with a neutral ES module target and reject Node imports or direct tool/MCP calls. Set `JEV_CLAUDE_VALIDATE=1` for the package test to run the installed static `claude plugin validate` command, without loading a coding session. Temporary fixtures and compiled verification outputs belong in the worktree's `.agent-work` directory and are removed after the check.

The preparation script downloads [Anthropic's public declarations at commit 58d6da1](https://github.com/anthropics/claude-code/blob/58d6da1e34d6cd1c6379dcbf568bd66f5f9b6102/mods/types/claude-code.d.ts) as an ignored local dependency at `tests/fixtures/claude-code.d.ts`. It reuses the file only when its hash matches, verifies downloaded bytes before atomic replacement, and fails before TypeScript on download or integrity failure. The declarations are not redistributed in Git or plugin packages. Their header names Claude Code 2.1.277. SHA-256 is `e51e637fbbebb2a6a49c4bdc3860a251c2ca2295884822dff0f4c3e3ec802163`. Relevant declarations include plugin root at line 2028, filesystem reads at line 2769 and stat at 2842, `FsStat` at 4148, `Next.origin` at 5310, `Origin` at 5941, `Register` at 7449, `TurnStepInput` at 10681 and streamed tool IDs at 10818. These are public-interface and offline checks, not acceptance of a loaded native runtime.

Blocking first steps were the approved specification, verified worktree and official API check. Independent workstreams belong to the root's shared routing, consultation and desktop owners. Root alone integrates shared contracts and generated distributions. The smallest Claude unit is the producer, pure causal consumer and opt-in package tested together. Native runtime loading, actual model/effort, security-guard interaction and live cancellation remain unproven until separately authorized real-host acceptance.
