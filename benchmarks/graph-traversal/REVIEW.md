## Verdict

**GO for a bounded plumbing prototype. Scored-launch acceptance is conditional on the checks below.** A precomputed ranked context packet can legitimately measure retrieval or context ordering. It cannot establish intelligent graph traversal. The minimum traversal prototype needs an interactive graph operation and observed downstream expansions. This is a design verdict, not acceptance of implementation or a measured Jev benefit.

The planned arithmetic is 3 bugs × 3 ranking arms × 2 hosts × 5 repetitions = 90 scored trials. Each host still has three independent bug clusters. Repetitions characterize run variation; they do not establish broad applicability across repositories or bug types. Report host results separately and treat uncertainty across three clusters as exploratory.

## Required design conditions

1. **Make traversal observable.** A host requests neighbors of a node or the current frontier, receives ordered node cards, and chooses what to expand or read next. Record the pre-fix graph identity, state and visited nodes, candidate packet hash, returned ordering, host-visible tool response, actual expansions/file reads, and terminal artifact. Preserve mandatory dependency coverage and an unvisited frontier. A ranking may change order, never make required branches inaccessible. A terminal claim that the agent used the graph is insufficient.

2. **Change ordering alone.** All arms use the same graph builder, seeds, candidate generation, node-card contents, evidence limits, tools and dependency policy. Graph-only uses a frozen deterministic edge/distance ordering. Cheap BM25 uses a frozen query, tokenizer and tie-break rule, tuned before scored outcomes. Jev uses a fixed Score rubric, context and model for independently scored nodes, with defined ties, malformed-response handling and deterministic fallback. Do not expose Jev-only rationales, additional snippets or scores that give its arm extra evidence. Record score requests and responses outside candidate-visible paths. A batch score is a ranking signal, not a calibrated probability of a complete repair.

3. **Distinguish equal mechanisms from equal trajectories.** Identical candidate packets are required for identical traversal states. Once rankings change visited nodes, later frontiers naturally differ. Do not force identical final context and then label it dynamic exploration. An optional replay of a shared frozen frontier isolates ranking quality, but the end-to-end claim still requires live traversal and repair. Graph access and ordinary source-search permissions must match across arms. An agent that ignores graph order or never invokes the tool remains in its assigned denominator, with uptake reported separately.

4. **Freeze provenance without leaking the answer.** Freeze exact repository and pre-fix revision, extracted source tree, graph-builder version/options, graph and node/edge hashes, coding model/effort, Jev model/rubric, adapter/tool configuration and hidden grader. Label syntactic, resolved and heuristic edges truthfully. Exclude future commits, fixed versions, PR text containing solutions and graders from candidate-visible material. Historical bugs may have been seen during model training; they are reproducible historical cases, not guaranteed unseen tasks. A withheld grader is not same-user OS isolation. If graph reads track edited files, define revision/invalidation rules; otherwise label the map as a frozen pre-fix map.

5. **Isolate the intervention.** Disable all other Jev hooks, reviews, approvals and routing in every arm, including Jev-ranked runs. Only the graph ranking path contacts Jev. Verify effective configuration and transport/delivery evidence for native Codex and QQ. Keep the same `gpt-6-astra` and high effort, while verifying each host's resolved identity rather than treating a requested string as proof. Use fresh owned sessions/workspaces without changing installed defaults, credentials, user sessions or the paused study.

6. **Count the whole operation.** Time graph construction, host startup, node packing, local BM25 work, Jev requests including retries/fallback, traversal, coding, grading and cleanup under explicit boundaries. Report graph construction once for a cold start and any amortized reuse separately. Do not time only the provider's response or only successful repairs. Keep provider token usage, cache semantics, known estimates and unknown billed dollars separate. Record all scheduled outcomes, including no traversal, unavailable Jev, fallbacks, denied tools, invalid configuration, incomplete artifacts and cleanup failures. None authorizes an unrecorded replacement trial.

## Minimum acceptance before the scored cohort

- A real native tool trace on each host establishes that graph output reached the model, the model expanded/read nodes afterwards, and the returned artifact was independently graded. Host integration must work before expensive cohort execution. This does not require every agent to follow the top rank.
- Deterministic isolated checks prove graph-only and BM25 order, Jev response parsing/ties/fallback, dependency retention, cycle handling and idempotent visited-state updates. A controlled rank-order change must appear unchanged in the delivered tool response. Do not use a grader answer to manufacture a successful demonstration.
- Frozen scheduling uses arm-order counterbalancing within each host/bug and keeps comparisons close in time. Five repeats cannot cover all six three-arm permutations equally within one bug; disclose the allocation and rotate it across bugs. Preserve every scheduled slot and use bug-cluster analysis, with per-bug outcomes visible.
- A single owned semaphore limits active native coding sessions across both hosts to two. Hold ownership through terminal/cancellation acknowledgement. Record native and Jev requests separately, along with concurrent workload and cache exposure. This experimental concurrency setting is not a product call quota.
- The primary result is complete repair under independent required behavior and regression tests, accepting valid alternative patches. Traversal counts, causal-location recall and time are secondary. Faster failure, a plausible patch, extra graph calls, or provider HTTP success do not prove benefit. Evaluate Jev against both graph-only and the tuned cheap arm before claiming value.
