# Candidate: reduce neutral hook context

Owner: root integration; hook source has one delegated implementation owner. The existing 0.5.1 development snapshots remain unchanged. This is a candidate for fresh confirmation, not an established performance improvement.

Observed trigger: early native hook traces repeatedly inject generic proceed, abstention and unavailable status prose. In the first two completed Claude treatment attempts, 21 transport receipts included eight abstentions; summed provider latency was 4.51 seconds. Correct artifacts occurred in both arms. The small partial sample establishes redundant output and accounting behavior, not a quality effect.

Journey: every currently eligible hook still consults Jev under the same unlimited policy and stores its provider/invocation receipt. A configurable delivery mode determines which advisory text is placed into the host context. Explicit MCP/CLI question responses are unchanged. SessionStart retains the existing consultation guidance; ordinary repeated UserPromptSubmit guidance is omitted in actionable mode.

State and authority: add `JEV_HOOK_ADVICE_MODE=all|actionable`, default `all` while evaluating. No schema migration, key access change, storage path change, policy budget, retry, approval or permission change. Existing durable receipts remain the audit truth. Unknown mode falls back to all for compatibility. Hook deadlines and failure behavior remain bounded.

Actionable mode emits assessed valid custom candidate selections and assessed reconsider/gather_evidence suggestions. It suppresses status-only abstained/unavailable/skipped/preview output and generic proceed selections from the exact built-in action taxonomy. It keeps the original classification calls and records. Clearly scope delivered suggestions using the hook event/domain; do not generate reasons Jev did not supply or imply authority.

Opt-in delivery configuration must be identical at every runtime entry of a confirmation treatment package. The off arm has no Jev consultation. Keep old development engine bytes and source identities. If a new confirmation compares repaired-on with off, do not describe the difference as repaired-on versus old-on.

Acceptance: meaningful fake-service tests demonstrate unchanged consultation/receipt counts, quiet neutral context, retained reconsider/gather-evidence/custom choices, SessionStart guidance, compatibility all mode, malformed/invalid-choice handling and both Codex and Claude output shapes. Typecheck, build, full local verification and independent source review pass. Fresh untouched confirmation checks correctness/completion/time/cost coverage; keep the feature opt-in or revert if unsupported or harmful. No global installed policy changes follow merely from a benchmark.
