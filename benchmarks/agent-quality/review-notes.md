## Findings

1. **P1. Treatment availability must not select the primary sample.** SPEC lines 23 and 33 can conflict. A configuration leak, wrong model, or missing intervention mechanism can invalidate a comparison. An assigned treatment trial that has a provider error, abstention, no relevant hook, or unused advice is still an observed treatment outcome. Freeze these categories separately. Keep every scheduled slot in operational success and coverage denominators. Keep missing artifact evidence distinct from a proven wrong artifact. Report valid-pair quality and missing-data sensitivity separately if needed. Never replace the primary estimate with successful-provider-call or advice-uptake subsets. A whole cohort with no functioning intervention supports an integration-failure conclusion, not an estimate of useful advice. This matches the canonical paired-v1 intention-to-treat rule.

2. **P1. Freeze the outcome and reducer before seeing results.** SPEC lines 33–37 name both assertion fraction and all-check pass without precedence and do not fix the aggregation or timeout timing rule. Make all-required-check pass the primary task outcome; assertion fraction is secondary. Within each host, pair by task, input hash, repetition, and frozen configuration. Compute on-minus-off differences, average repeats within each task, then give tasks equal weight. Resampling must retain all repeats/arms of a task together. Five development tasks and three confirmation tasks remain five and three task clusters, not 25/15 independent tasks. Prefer per-task estimates/ranges and explicitly unstable uncertainty over a significance claim. Freeze whether timing means total trial wall time or agent time. Retain actual elapsed time for every failure and timeout; a fast failure is not a speed benefit. Any both-correct or success-only timing subset must disclose selection and its denominator next to all-scheduled correctness. Do not impute missing token/cost observations to zero or present known subtotals as complete totals.

3. **P1. Fix efficacy and repaired-configuration efficacy are different comparisons.** SPEC lines 15 and 41 allow repaired-on versus off on fresh tasks after examining development results. That can establish the repaired setup's held-out effect. It cannot isolate improvement caused by the fix against original-on, because the task cohort also changed. The smallest correction is to limit the claim and prove the concrete integration repair with regression evidence. If a numerical repair-effect claim is required, freeze original-on and repaired-on on the same untouched confirmation tasks before any confirmation outcome is exposed. Do not add that arm merely for ceremony. Freeze the selection rule, version, and intended claim before confirmation; after inspection, those tasks become used validation data and cannot support another fresh-confirmation claim.

4. **P2. Freeze the treatment mechanism and delivery evidence per host.** SPEC line 23 has the right requirement, but receipt counts alone cannot satisfy it. The frozen host record should name the enabled Jev features, pinned Jev model/aliases, thresholds, requested/resolved coding model and effort, and common non-Jev instructions/tools. Each advice record needs linkage from triggering run/event through provider receipt to actual host-visible feedback or gate result. Preserve delivery status and a transcript/event pointer or hash. Distinguish delivered advice, abstention, unavailable advice, policy suppression, and passive observation. Describe uptake from subsequent relevant actions as agree/contradict/unknown; temporal proximity is not proof of causation. QQ routing must stay disabled in both arms, and native final-review/approval intervention must be specified rather than replaced by an external observer. Check effective control configuration at each trial, not only once before the batch. Wrong resolved identities remain retained invalid-identity rows.

5. **P2. Declare the practical blinding boundary.** Outside-workspace graders are withheld from the prompt, not OS isolation for a same-user process. SPEC line 19 should say this explicitly and state the actual command/filesystem/network boundary. Freeze hashes of protected fixture/oracle inputs and preserve command/read evidence for attempted access. Flag contamination without replacing the failed scheduled slot. Keep treatment labels and result paths out of candidate-visible arguments and diagnostics where possible. Do not describe unobserved external reads as ruled out. Existing authorization does not call for building a new sandbox merely to make stronger wording possible.

6. **P2. Disclose pre-exposure, follow-ups, and cache/order handling.** SPEC lines 13, 19 and 21 should freeze the exact preflight task IDs, follow-up bytes and dispatch rule, and whether timeoutMs is one whole-trial budget across every turn. The same frozen organic follow-ups go to both arms without hidden-grader feedback or result-dependent retries. A preflight task reused in the scored development cohort is already exposed and can warm provider caches; record that history and do not call the cohort cold-cache or pristine. Freeze a seeded/counterbalanced order with each pair close in time, record concurrent workloads, and retain cache telemetry. With five repeats, exact balance within every task is impossible; document the 3/2 allocation and reverse across tasks/hosts rather than claiming exact per-task parity.
